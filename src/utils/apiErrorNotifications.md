# Ошибки запросов

`notifyApiError` и `ignoreApiError` экспортируются из корня isp-admin-ui-kit и из utils.

Для ошибки метода используйте исходный объект ошибки:

```ts
updateItem(values)
  .unwrap()
  .then(() => message.success('Изменения сохранены'))
  .catch((error) => notifyApiError(error, 'Не удалось сохранить изменения'))
```

Если ошибка уже объяснена полем формы или отдельным окном, перед отображением вызовите `ignoreApiError(error)`. Это отменит запасное уведомление интерцептора. Не используйте `message.error` для ошибок запросов: такой вызов не участвует в общей обработке. Локальная проверка введённых данных может использовать обычный message.

Интерцептор планирует общее уведомление на следующий проход очереди. Обработчики Promise успевают сообщить конкретную причину или обработать ошибку в форме. Если локального обработчика нет, остаётся общее уведомление. Повторное обращение к уже обработанному объекту ошибки ничего не показывает.

Состояние хранится в WeakMap: ошибки не изменяются, в том числе замороженные объекты в Redux. Разные ошибки с одинаковым текстом не склеиваются. Не пересоздавайте и не копируйте объект ошибки перед передачей обработчику.

Отменённые запросы не уведомляют пользователя. При нескольких ответах 401 показывается одно сообщение об истёкшей сессии с переходом на вход.

Проверка без HTTP: `node --test tests/api-error-notifications.test.mjs`.
