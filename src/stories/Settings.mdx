## Настройка Monaco Editor

> ⚠️ **Критически важно:** Компоненты с редактором кода не будут работать без правильной настройки loader.

В точке входа проекта (`src/index.ts` или `src/main.tsx`) необходимо выполнить инициализацию **до** рендера приложения:

```tsx
import * as monaco from 'monaco-editor';
import loader from '@monaco-editor/react';

// Конфигурация
loader.config({ monaco });

// Инициализация
await loader.init();
```

**Полный пример точки входа:**

```tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import * as monaco from 'monaco-editor';
import loader from '@monaco-editor/react';
import { baseSetupStore, AdminBase } from 'isp-admin-ui-kit';
import { Provider } from 'react-redux';
import { BrowserRouter } from 'react-router-dom';

const init = async () => {
  // 1. Monaco Editor
  loader.config({ monaco });
  await loader.init();

  // 2. Store
  const store = baseSetupStore();

  // 3. Render
  ReactDOM.createRoot(document.getElementById('root')!).render(
    <React.StrictMode>
      <Provider store={store}>
        <BrowserRouter>
          <AdminBase />
        </BrowserRouter>
      </Provider>
    </React.StrictMode>
  );
};

init();
```

## Настройка Monaco Worker (Vite / Rollup)

⚠️ Важно: Если ваше приложение или библиотека собирается через Vite или Rollup, необходимо явно подключить Monaco Workers.
Без этого редактор может выдавать ошибки или не работать подсветка синтаксиса.

🔧 Пример настройки

Добавьте конфигурацию до инициализации loader:
```jsx
import { loader } from '@monaco-editor/react';
import * as monaco from 'monaco-editor';

// импорт worker-файлов
import editorWorker from 'monaco-editor/esm/vs/editor/editor.worker?worker';
import cssWorker from 'monaco-editor/esm/vs/language/css/css.worker?worker';
import htmlWorker from 'monaco-editor/esm/vs/language/html/html.worker?worker';
import jsonWorker from 'monaco-editor/esm/vs/language/json/json.worker?worker';
import tsWorker from 'monaco-editor/esm/vs/language/typescript/ts.worker?worker';

// настройка окружения Monaco
self.MonacoEnvironment = {
    getWorker(_: unknown, label: string) {
        if (label === 'json') return new jsonWorker();
        if (label === 'css' || label === 'scss' || label === 'less') return new cssWorker();
        if (label === 'html' || label === 'handlebars' || label === 'razor') return new htmlWorker();
        if (label === 'typescript' || label === 'javascript') return new tsWorker();
        return new editorWorker();
    },
};

// конфигурация loader
loader.config({ monaco });

// инициализация
loader.init();
```

## Работа с компонентом AdminBase

Компонент `AdminBase` — это основной компонент библиотеки, который предоставляет готовую структуру админ-панели.

### Параметры компонента

| Название | Описание | Пример |
|----------|----------|--------|
| `customRouters` | Массив объектов маршрутов | `[{ route, element, label, key, ... }]` |
| `configProviderProps` | Пропсы для `ConfigProvider` из Ant Design | `{ theme: lightTheme, locale: ru }` |
| `defaultRoutePath` | Путь для редиректа с главной страницы (`/`) | `"/modules"` |
| `excludePermissions` | Массив пермишенов для скрытия страниц | `[PermissionKeysType.user_view]` |

### Примеры использования

**Базовое использование:**

```tsx
import AdminBase from 'isp-admin-ui-kit';

<AdminBase />;
```

**Полная конфигурация:**

```tsx
<AdminBase
  customRouters={customRouters}
  configProviderProps={{ theme: lightTheme, locale: ru }}
  defaultRoutePath="/dashboard"
  excludePermissions={excludePermissions}
/>;
```

const { data, isLoading, isError } = baseApiServices.roleApi.useGetAllRolesQuery();

## Интеграция с кастомным стором

Функция `baseSetupStore` принимает необязательный параметр `apiServices` для подключения пользовательских редьюсеров и RTK Query сервисов.

### Параметры

| Название | Описание | Пример |
|----------|----------|--------|
| `apiServices` | Объект кастомных редьюсеров и слайсеров | `{ modulesServiceApi, UIReducer }` |

### Пример

```tsx
import { baseSetupStore } from 'isp-admin-ui-kit';

const apiServices = {
  modulesServiceApi,
  UIReducer,
};

const store = baseSetupStore(apiServices);
```

## Подключение темы

Библиотека использует тему Ant Design. Для кастомизации передайте параметры через `configProviderProps`:

```tsx
import AdminBase from 'isp-admin-ui-kit';
import { lightTheme } from './theme';
import { ru } from 'antd/locale';

<AdminBase configProviderProps={{ theme: lightTheme, locale: ru }} />;
```

Для добавления динамических стилей к кастомным компонентам используйте CSS-переменные Ant Design.

## Настройка роутеров

Компонент `AdminBase` поддерживает кастомную маршрутизацию через параметр `customRouters`.

> ⚠️ **Важно:** Для корректной работы пунктов меню значения полей `route` и `key` должны совпадать!

### Параметры маршрута

| Название | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `route` | `string` | ✅ | Путь маршрута |
| `element` | `ReactNode` | ✅ | Компонент для отображения |
| `label` | `string` | ❌ | Название в меню |
| `key` | `string` | ✅ | Уникальный ключ (должен совпадать с `route`) |
| `permissions` | `string[]` | ✅ | Список разрешений; по умолчанию достаточно хотя бы одного |
| `permissionMode` | `'any' \| 'all'` | ❌ | `any` (по умолчанию) — хотя бы одно право; `all` — все права |
| `visibilityMode` | `'permissions' \| 'children'` | ❌ | `permissions` (по умолчанию) — собственные права пункта; `children` — наличие доступных детей |
| `icon` | `ReactNode` | ❌ | Иконка маршрута |
| `children` | `Array` | ❌ | Вложенные маршруты |
| `className` | `string` | ❌ | CSS-класс для пункта меню |

Без новых настроек сохраняется прежняя проверка: достаточно одного права из `permissions`, в том числе у родителей.
Для пункта, требующего нескольких прав одновременно, задайте `permissionMode: 'all'`.
Для группы, которая должна отображаться при наличии хотя бы одного доступного ребёнка, задайте `visibilityMode: 'children'`.
В этом режиме собственные `permissions` группы не проверяются: можно передать `[]`.
Настройки задаются для каждого пункта отдельно и не наследуются детьми.
Отдельный пункт с `permissions: []` скрыт; для пункта без ограничений используйте `permissions: ['ALWAYS_VIEW']`.

### Пример

```tsx
const customRouters = [
  {
    route: '/dashboard',
    key: 'dashboard',
    element: <Dashboard />,
    label: 'Dashboard',
    permissions: ['admin', 'user'],
    icon: <DashboardIcon />,
    className: 'custom-menu-item',
  },
];

<AdminBase customRouters={customRouters} />;
```

## Пример использования

### Скрытие страниц через `excludePermissions`

```tsx
import { PermissionKeysType } from 'isp-admin-ui-kit';

const excludePermissions = [
  PermissionKeysType.user_view,
  PermissionKeysType.session_view,
  PermissionKeysType.role_view,
];

<AdminBase excludePermissions={excludePermissions} />;
```

### Проверка прав в компоненте

```tsx
import { useAppSelector } from 'isp-admin-ui-kit';
import { PermissionKeysType } from 'isp-admin-ui-kit';

const MyComponent = () => {
   const { hasPermission } = useRole()

  const isUpdateRole = hasPermission(PermissionKeysType.role_update)
  const isCreateRole = hasPermission(PermissionKeysType.role_add)

  return (
    <>
      {isUpdateRole && <UpdateButton />}
      {isCreateRole && <CreateButton />}
    </>
  );
};
```

### Настройка прав для маршрута

```tsx
import { PermissionKeysType } from 'isp-admin-ui-kit';

const customRouters = [
  {
    route: '/users',
    key: 'users',
    element: <UsersPage />,
    label: 'Пользователи',
    permissions: [PermissionKeysType.user_view],
    icon: <UsersIcon />,
  },
  {
    route: '/roles',
    key: 'roles',
    element: <RolesPage />,
    label: 'Роли',
    permissions: [PermissionKeysType.role_view],
    icon: <RolesIcon />,
  },
];

<AdminBase customRouters={customRouters} />;
```

---

> 💡 **Совет:** Для скрытия целых разделов рекомендуется использовать ключи `*_view` соответствующих пермишенов. Детальные права (`*_add`, `*_edit`, `*_delete`) используются для управления доступом к действиям внутри страниц.

## Обновление версии

Для обновления версии пакета:

1. Обновите значение `version` в `package.json`
2. Добавьте запись в `CHANGELOG.md`
3. Создайте коммит с сообщением: `up version to X.Y.Z`

```bash
git commit -m "up version to X.Y.Z"
git push
```
