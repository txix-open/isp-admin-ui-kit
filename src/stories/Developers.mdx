# Для разработчиков

Раздел предназначен для описания процессов взаимодействия с кодовой базой проекта. Здесь собраны правила, стандарты и инструкции для разработчиков библиотеки.

## Структура проекта

Весь исходный код расположен в папке `src`:

| Директория    | Назначение                                          |
|---------------|-----------------------------------------------------|
| `assets`      | Ресурсы проекта (изображения, шрифты и др.)         |
| `components`  | Переиспользуемые UI-компоненты                      |
| `constants`   | Файлы с константами                                 |
| `hooks`       | Кастомные React-хуки                                |
| `pages`       | Страницы приложения                                 |
| `routes`      | Маршруты и конфигурация роутинга                    |
| `services`    | API-клиенты и бизнес-логика                         |
| `stores`      | Управление состоянием (Redux)                       |
| `stories`     | Файлы для Storybook                                 |
| `type`        | Определения типов TypeScript                        |
| `ui`          | Базовые стили и UI-решения                          |
| `utils`       | Вспомогательные утилиты и функции                   |
| `widgets`     | Сложные, независимые модули интерфейса              |

> 📌 **Точка входа:** Файл `src/index.ts` экспортирует все публичные модули библиотеки.

## Правила написания кода

### Название файлов

| Тип файла       | Именование              | Пример                      |
|-----------------|-------------------------|-----------------------------|
| Основной файл   | `index.tsx`             | `UserProfile/index.tsx`     |
| Файл типов      | `*.types.ts`            | `user-profile.types.ts`     |
| Файл стилей     | `*.scss`                | `user-profile.scss`         |
| Тесты           | `*.test.tsx`            | `user-profile.test.tsx`     |

### Стилизация

Используется **БЭМ-нейминг** для CSS-классов. Стили должны быть изолированы внутри компонента.

```css
.user-profile {
  &__header {
    display: flex;
    
    &--collapsed {
      height: 40px;
    }
  }
  
  &__avatar {
    width: 100px;
  }
}
```

**Правила:**
- Используются только классы (без ID и тегов)
- Вложенность не более 3 уровней
- Переменные SCSS хранятся в `src/ui/variables.scss`

### Типизация

| Правило                          | Пример                                      |
|----------------------------------|---------------------------------------------|
| Типы в отдельные файлы           | `component-name.types.ts`                   |
| `interface` для публичного API   | `export interface ComponentPropsType {}`    |
| `type` для сложных объединений   | `type ActionType = 'edit' \| 'delete'`      |
| Суффикс `Type` в названиях       | `UserProfilePropsType`                      |

```ts
// ✅ Правильно
export interface UserProfilePropsType {
  user: User;
  onEdit?: (user: User) => void;
}

type UserProfileActions = 'edit' | 'delete' | 'view';

// ❌ Неправильно
interface Props { ... } // Без суффикса Type
type UserProps = { ... } // Interface лучше для объектов
```

### Структура компонента

Код компонента должен следовать порядку **от общего к частному**:

```tsx
// 1. Импорты
import React from 'react';
import { useSelector } from 'react-redux';

// 2. Типы
import { ComponentPropsType } from './component.types';

// 3. Стили
import './component.scss';

// 4. Компонент
export const Component: React.FC<ComponentPropsType> = (props) => {
  // 4.1. Инициализация состояния
  const [state, setState] = useState();
  
  // 4.2. Подписки (селекторы, контекст)
  const data = useSelector(selectData);
  
  // 4.3. Эффекты
  useEffect(() => {
    // логика
  }, [deps]);
  
  // 4.4. Обработчики
  const handleClick = () => {};
  
  // 4.5. Рендер
  return <div className="component">{/* JSX */}</div>;
};

// 5. Экспорт
export default Component;
```

## Сборка и публикация

### Локальная сборка

```bash
# Установка зависимостей
npm install

# Сборка пакета
npm run build

# Запуск Storybook
npm run storybook
```

### Экспорт компонентов

1. Каждый компонент должен иметь `export default` в своём файле
2. Добавьте экспорт в `src/index.ts`:

```ts
// src/index.ts
export { default as AdminBase } from './components/AdminBase';
export { baseSetupStore } from './stores/baseSetupStore';
export { baseApiServices } from './services/baseApiServices';
export { PermissionKeysType } from './type/permissions.types';
```

## Обновление версии

Коммит с обновлением версии должен быть **последним** в задаче.

### Шаги обновления
| Шаг | Действие                                    | Пример                          |
|-----|---------------------------------------------|---------------------------------|
| 1   | Обновить `version` в `package.json`         | `"version": "1.2.3"`            |
| 2   | Описать изменения в `CHANGELOG.md`          | `## [1.2.3] - 2024-01-15`       |
| 3   | Закоммитить изменения                       | `git commit -m "up version to 1.2.3"` |
| 4   | Отправить в репозиторий                     | `git push`                      |
| 5   | Дождаться публикации в npm                  | ~7 минут                        |

### Семантическое версионирование

Используйте [SemVer](https://semver.org/):

- **MAJOR** (`X.0.0`) — ломающие изменения
- **MINOR** (`0.X.0`) — новые функции (обратно совместимые)
- **PATCH** (`0.0.X`) — исправления багов
